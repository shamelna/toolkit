# Kaizen Academy — PDF Report Design Guidelines
### Toolkit Applications · Standard v1.0 · March 2026

> These guidelines define the standard structure, visual identity, content rules, and lead-generation best practices for every PDF report generated by Kaizen Academy toolkit applications. All apps — histogram analyser, Pareto builder, control chart generator, VSM tools, and any future tools — must follow this specification to deliver a consistent, branded, and conversion-focused experience.

Use **Helvetica** (or Arial as fallback) exclusively. Never use decorative or serif fonts in toolkit reports.

- Minimum body font size: **9pt**

## 3. Chart & Visualisation Standards

**Bar / Column Charts**
Bars filled `#FFD559`. Specification limit lines in red (`#CC0000`) dashed. Mean line in white or dark grey. Normal distribution overlay curve in dark grey if sample size ≥ 30. Background: white with light grey horizontal gridlines only.

**Axes & Labels**
X-axis label: measurement name + unit. Y-axis label: Frequency or Count. Font: Helvetica 8–9pt, dark grey. Tick marks on both axes. No chart border/box — use open axis style.

**Colours — DO NOT USE**
Red for data bars. Green for bars. Gradient fills. 3D effects. Drop shadows. More than 3 colours in any single chart.

**Cumulative Frequency Line**
Rendered as a dashed line in mid-grey (`#888888`). Secondary Y-axis on right side, labelled "Cumulative %".

**Specification Limits**
LSL and USL shown as vertical dashed red lines with text labels ('LSL' / 'USL') at top of chart area. If no limits are set by user, omit the lines and note "No specification limits defined" in the interpretation section.

**Process Capability Callout**
Display Cp and Cpk as a yellow-background callout box overlaid on the chart, bottom-right corner. Show green indicator if Cpk ≥ 1.33, amber if 1.0–1.33, red if < 1.0.

## 4. Content Writing Rules

### Executive Summary — Writing Formula

Write 2–4 sentences:
- **Sentence 1:** State the key finding in plain language (e.g. "Your process average is well-centred between your limits")
- **Sentence 2:** Highlight any risk or opportunity
- **Sentence 3 (optional):** Connect to what the user should do next

Never start with "The histogram shows…"

### Interpretation Section — Plain Language Rules

- Explain what the distribution shape means (normal, skewed left/right, bimodal, uniform)
- State whether the process is centred — use actual numbers: "Your mean (3.515) sits 0.115 units above the midpoint of your limits"
- Explain Cp vs Cpk in one sentence if they differ significantly
- Flag any unusual patterns: outliers, gaps, truncation at a limit
- End with a "next step" sentence that naturally leads into the course CTA

### Recommendations — Dynamic Rules

Recommendations **must** be generated from actual data conditions, not static text. Use conditional logic in the app to select the appropriate recommendation:

| Condition | Recommendation Text |
|-----------|---------------------|
| Cpk ≥ 1.33, centred | Process is capable and centred. Maintain current parameters and implement SPC monitoring. |
| Cpk 1.0–1.33 | Process is marginally capable. Investigate sources of variation. Consider tightening controls. |
| Cpk < 1.0 | Process is not capable. Immediate investigation required. Use root cause analysis tools. |
| Off-centre (mean differs from midpoint by > 10% of range) | Process is capable but off-centre. Review and adjust process setpoint. |
| Skewed distribution | Distribution is non-normal. Check for process drift, mixed batches, or measurement error. |
| Bimodal distribution | Two peaks suggest two distinct process streams. Stratify data by shift, machine, or operator. |
| No spec limits set | No specification limits were provided. Define LSL/USL to enable capability analysis. |

## 7. Content Rules — Always & Never

### ✓ Always Include

- Kaizen Academy logo on every page header
- Report generation date and tool name in the header
- Plain-language executive summary as the first content section
- Dynamic, data-driven recommendations — never static boilerplate
- Process Capability metrics (Cp, Cpk) wherever relevant to the tool
- One CTA block per report with the correct course link and `kaizen20` promo code
- Certificate issuer noted as "Kaizen Academy Australia" in the CTA block
- Website URL in the footer: `www.continuousimprovement.education`
- Page numbers in the footer

### ✗ Never Include

- Physical street address
- Phone numbers
- Course or content length specifications (e.g. "4 hours of video")
- Generic recommendations that don't reflect the actual data
- More than one CTA block per report
- Made-up testimonials or fabricated social proof
- Competitor brand names or logos
- Email subjects or newsletter preview text
- Colours outside the brand palette
- 3D chart effects, gradients, or decorative borders

## 9. Recommended Technology Stack

### Guiding Principle

Design reports as **HTML + CSS first**, then convert to PDF. This gives full brand control — the black header band, yellow accent strip, embedded logo, styled CTA block, and chart overlays are all standard HTML/CSS elements. Design changes require no PDF library code changes, only CSS edits.

---

### Primary Recommendation: Playwright (Headless Chrome → PDF)

Playwright launches a headless Chrome browser, renders your HTML report page, and exports it as a pixel-perfect PDF. It is the most reliable option for complex, branded layouts.

- **Languages:** Python, Node.js, Java, .NET
- **Best for:** Reports with charts, custom fonts, branded headers, complex layouts
- **Cost:** Free / open source
- **Docs:** https://playwright.dev/docs/api/class-page#page-pdf
- **Hosted/API option (no server required):** https://www.browserless.io

**Python install:**
```bash
pip install playwright
playwright install chromium
```

**Basic usage:**
```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.set_content(html_string)          # or page.goto("http://localhost/report")
    page.pdf(
        path="report.pdf",
        format="A4",
        margin={"top": "20mm", "bottom": "20mm",
                "left": "20mm", "right": "20mm"},
        print_background=True              # Required for coloured backgrounds
    )
    browser.close()
```

> ⚠️ Always set `print_background=True` — without it the black header band and yellow elements will not render.

---

### Secondary Recommendation: WeasyPrint (Python)

WeasyPrint converts HTML + CSS directly to PDF without a browser. Simpler setup than Playwright, no Chromium dependency, good for server environments with limited resources.

- **Language:** Python only
- **Best for:** Text-heavy reports, server-side generation, simpler layouts
- **Limitation:** Charts must be pre-rendered as PNG images before injection into the HTML template
- **Cost:** Free / open source
- **Docs:** https://doc.courtbouillon.org/weasyprint/stable/

**Python install:**
```bash
pip install weasyprint
```

**Basic usage:**
```python
from weasyprint import HTML

HTML(string=html_string).write_pdf(
    "report.pdf",
    stylesheets=["report_styles.css"]
)
```

### Chart Rendering

Charts must be pre-rendered and embedded as PNG images into the HTML template before PDF conversion. Do not rely on JavaScript-based chart libraries to render inside Playwright unless you explicitly wait for render completion.

| Library | Language | Notes |
|---------|----------|-------|
| **Matplotlib** | Python | Recommended. Full control over bar colours, LSL/USL vertical lines, mean line, normal curve overlay. Export as PNG. |
| **Plotly (static export)** | Python | Use `plotly.io.write_image()` with kaleido. Good for interactive-to-static workflow. |
| **Chart.js** | JavaScript | Use with Playwright — wait for `chart.render()` to complete before calling `page.pdf()`. |

**Matplotlib example — histogram with LSL/USL vertical lines:**
```python
import matplotlib.pyplot as plt
import matplotlib.patches as mpatches

fig, ax = plt.subplots(figsize=(8, 5))

# Bars in Kaizen Academy yellow
ax.bar(bin_edges[:-1], counts, width=bin_width,
       color="#FFD559", edgecolor="#1A1A1A", linewidth=0.8, align="edge")

# LSL and USL as vertical dashed red lines
ax.axvline(x=lsl, color="#CC0000", linestyle="--", linewidth=1.5, label=f"LSL: {lsl}")
ax.axvline(x=usl, color="#CC0000", linestyle="--", linewidth=1.5, label=f"USL: {usl}")

# Mean line
ax.axvline(x=mean, color="#2E2E2E", linestyle="-", linewidth=1.2, label=f"Mean: {mean:.4f}")

# Label LSL/USL at top of chart
ax.text(lsl, ax.get_ylim()[1] * 0.95, "LSL", color="#CC0000",
        fontsize=8, ha="center", fontweight="bold")
ax.text(usl, ax.get_ylim()[1] * 0.95, "USL", color="#CC0000",
        fontsize=8, ha="center", fontweight="bold")

# Axis labels
ax.set_xlabel("Measurement Value", fontsize=9, color="#2E2E2E")
ax.set_ylabel("Frequency", fontsize=9, color="#2E2E2E")

# Clean style — no top/right border
ax.spines["top"].set_visible(False)
ax.spines["right"].set_visible(False)
ax.yaxis.grid(True, color="#EEEEEE", linewidth=0.7)
ax.set_axisbelow(True)

ax.legend(fontsize=8)
plt.tight_layout()
plt.savefig("histogram.png", dpi=150, bbox_inches="tight")
plt.close()
```

### Recommended Stack Summary

| Layer | Tool | Notes |
|-------|------|-------|
| Chart rendering | Matplotlib | Pre-render to PNG, embed in HTML |
| Report layout | HTML + CSS | Brand styles, logo, CTA block |
| PDF conversion | Playwright | Primary recommendation |
| PDF conversion (alt) | WeasyPrint | Simpler, Python-only alternative |
| Hosted PDF API | Browserless.io | No server required, Playwright-compatible |
| Greek symbols / Unicode | Use plain text labels | "Mean", "Std Dev" — avoids encoding corruption |

---

### Common Pitfalls to Avoid

**ReportLab** — builds layout programmatically. Greek symbols (`μ`, `σ`) corrupt on export, column widths require manual calculation, every design change requires code changes. Not recommended for branded reports.

**jsPDF** — poor support for complex layouts and custom fonts. Avoid for multi-section branded reports.

**Unicode Greek characters in PDF libraries** — always use plain text equivalents ("Mean", "Std Dev", "Cp", "Cpk") unless your library explicitly supports UTF-8 glyph rendering. This prevents the `¼` and `Ã` corruption seen in earlier report versions.
